## Map

- **imaging** (pure TS, browser/Worker/Node; today no dependency on core): `image.ts` (RGBA, luminance, stable trig), `pdfPages.ts` (open PDF with our decoders, embedded scan or `renderPage`; **no version**), `png.ts`, `rotate.ts` (`ROTATE_VERSION`), `scale.ts` (`SCALE_VERSION`, `CLAUDE_IMAGE_LIMIT`), `crop.ts` (`Box`, `boxProblem`, `CROP_VERSION`), `draw.ts` (`LayoutSystem`, `drawLayout`, `DRAW_VERSION`), `skew.ts` (`findSkew` **no version**, `deskewAngle` + `DESKEW_VERSION`, private `rotateGray`), `fingerprint.ts` (`asStored` ↔ `decodePng`), `regions.ts` (scripts only), `testPages.ts`.
- **core** `/pdf` (`drawPage`, `PDFJS_DATA`) and `/pdfjs-assets` (Vite plugin): used by web PdfView and eval PdfPane.
- **web, images:** `rasterize.ts` (`PageRecipe`, `pageRecipe()`, stage key), `pageImages.ts` (RPC client; recipe types `Page ⊂ Straight ⊂ ModelPage/Crop ⊂ Drawn/Layout/MarkedCrop`, only `pageRecipe` has a constructor; `cachedOr` key → OPFS → worker → cache → fingerprint check), `pageImageWorker.ts`, `imageCache.ts` + `cacheLru.ts` (OPFS + memory fallback, two LRUs), `pdf.ts`/`PdfView.tsx`, `ImagesDiffer.tsx`.
- **web, Worker RPC:** three hand-written clients (`pageImages`, `rendering`, `meiValidation`) and three worker shells (`pageImageWorker`, `renderWorker`, `meiCheckWorker`). The last two serve component D (MEI) but the RPC is B's.
- **web, geometry:** `Box` spelled 6× (imaging, notation, prompts ×2, fixLayout, schema), `{box, barLines}` 3×; crop helpers in `extract.ts` (`MARGINS`, `systemCropBox`, `stretchCropBoxes`, `stretchBox`, `onPage`); box editing in `fixLayout.ts`; `handles.ts`, `viewBounds.ts`.
- **page stages:** `skewAnalysis.ts`/`runSkewAnalysis.ts` (stores `Skew` per page), `fixSkew.ts`/`finishFixSkew.ts`/`SkewEditor.tsx`, prompts `layout.ts` (`checkLayoutAnswer`, `LAYOUT_ROUNDS`), `layout.ts`/`runLayout.ts` (straightens by `deskewAngle`, up to 3 rounds, stores `PageLayout`), `fixLayout.ts`/`finishFixLayout.ts`/`LayoutEditor.tsx`, `pageEditor.tsx` (viewport, gestures, `useSaver` with one user); views of both in `ArtifactView.tsx` (`LinesOverlay`, `LayoutPageView`, `PageImageView`, `Filmstrip`).
- **Contracts:** (1) recipe key = `keyOf(recipe)` names the OPFS file, the fingerprint row **and the image in every LLM request key** (so any change to a recipe's shape re-prices every LLM call downstream); (2) `asStored` ↔ `decodePng` (pinned by a test); (3) "lines" content `{lines}` for `skew` and `lines` outputs; (4) `layout` content `PageLayout` in fractions of the page straightened by its own `angle`, read by every crop; (5) stretch k = `[edges[k-1], edges[k]]` in extract.ts and mei.ts; (6) crop↔page maps must be inverses; (7) worker request/response unions shared by type import; (8) pdf.js folders ×3; (9) editor saves = `PUT /api/content` + checked `POST …/outputs` + fingerprints, under A's lock.

### P1: bugs that hurt now
- **B1. SkewEditor saves each page on its own chain** [19 #1; A4]: `useSaver` lives in the per-page editor (SkewEditor 111, remounted per page), so editing page 2 while page 1's save is in flight sends two checked POSTs with one version → second refused as "changed on another device", plus App's dialog. LayoutEditor has one chain per editor. Fix: A4 (queue per project, monotonic versions) first; then one `useSaver` per stage held by the editor shell (B21). certain (mechanism), check (frequency on a phone). Keys: none.
- **B2. Editors' `saved` cache never cleared, written before the save** [19 #3; 20 #1 for forms]: SkewEditor 45, LayoutEditor 64 (and fieldList, D/F), pageEditor 321 / LayoutEditor 114 set the entry before `store`. After a failed save, reopening shows the unsaved state as stored while Finish records the server's older content; comments promise eviction "until the pipeline is fetched again" that doesn't exist. Fix: set after success and drop when the pipeline's content hash equals it, or drop the cache. certain (comment lies), check (impact: failed saves). Keys: none.
- **B3. Bar lines at, past or on top of the box edges and each other are accepted** [02 #7; 19 #5; verified prompts layout.ts 95–97]: `checkLayoutAnswer` accepts lines up to 0.02 outside the box and stores them unclamped, and accepts a line at the box's end and duplicates; the editor's `addBarLine` clamps a tap onto the edge and allows two at one place. Results: inverted stretch (extract.ts `stretchBox` left > right, MEI `zone` with `lrx < ulx`, issue boxes drawn nowhere) or zero-width stretch (crop of margins only, an empty stretch to classify). Fix: one `normalizeBarLines(system, ε)` in core box.ts (drop lines within ε of an edge or outside, merge closer than ε, sort), used by `checkLayoutAnswer`, `addBarLine`/`moveBarLine`/`withinBox`; tests. certain (path), check (how often answers hit it). Keys: `checkLayoutAnswer` is part of `layout`'s version → bump it: layout stage re-runs from the call cache (free); stored layouts change only where normalized → extract/review requests for those systems only (paid, few). Old stored layouts untouched.
- **B4. A box near a system's edge "covers" the neighbour; five rules for "which system"** [02 #3, #4; 18 #3]: review.ts 28 `placesOf` counts a system when the box overlaps its tight box OR its crop (comment says "else"), crop margins are 15% of the height, so a box at the top of system 5 also hits 4: human review refuses a valid clarification ("systems 4, 5, 6"), apply_review starts at 4 with window [4,5] and misses 6, runApplyReview files it under 4 while the Transcription shows it under 5. Other rules: transcription `homeOf`, HumanReviewCards `where`, review's image system, `systemsOf()[0]`. Fix: crop only as fallback; one `systemsOf`/`homeOf` in D's `issues.ts` on core's `intersection`; test with close systems. certain. Keys: apply_review requests change where the window was wrong (paid, rare). **Owner: D, with B's geometry.**
- **B5. `checkMeiText` can wait forever** [04 #1]: meiValidation has no `error` listener and no timeout; if the worker chunk 404s (a tab open across a deploy) or libxml2's WASM fails, the handshake never comes, the cached promise never settles, Apply in FixMeiView and Finish of `fix_mei` hang. Fix: B20's shared client (reject, reset, retry); quick fix as rendering.ts. certain. Keys: none.
- **B6. Layout's and skew's notes wrong after a resumed run** [06 #3]: runLayout 51/114 counts systems and flagged pages only on pages made in this run; runSkewAnalysis 30/41 likewise. Fix: compute the note from the stage's final outputs (runPlan passes them), or preload like extract. certain. Keys: none (notes are stage fields).
