## Map

- **The call path** (browser → Worker → provider): web `llm.ts` `ask` (two rounds: recipe keys only → `{imagesNeeded}` → make images, size check, ask again; `stageModelConfig`, `modelKey`, image/request limits) → web `api.ts` `callLlm`/`streamedAnswer` (JSON or SSE via core `readSse`) → Worker `llmRoutes.ts` `/llm` (stage checks → `keyedRequest` → cache lookup (earliest `ok` row) → images needed → `prepareCall` (config, secrets, price, cap, `createAdapter`) → SSE around `runCall` (insert `running` row, `started`, provider or replay, cost/VAT/UPDATE, or error record)) → `llm/index.ts` factory → adapters (`anthropic.ts` via SDKs, `google.ts` + `openrouter.ts` plain fetch + `readSse`, `googleServiceAccount.ts` JWT) / `fake.ts` / `replay.ts` (answers by place from recorded calls). Progress: core `CallEvent` → web `callProgress.ts` (`ItemProgress` shown; `CallProgress` dead) + `itemTiming.ts` (per-item counters for run times).
- **Answers:** schemas in `packages/prompts` (five stages, four builder copies), `*FromModel` conversions (lensForm.ts, review.ts, applyReview.ts, analyze's flat↔nested), validated five ways (layout by hand, analyze by `shapeProblem`, extract/review/apply_review top level only, then notation/web checks); a returned `problem` → `markUnusable` (×8, failure swallowed); a thrown check → nothing marked, call stays `ok` and cached.
- **Model list:** gather scripts (Node, untyped, outside tsconfig) → `model-list/*.json` + `schema.json` (validated by Worker `llm/jsonSchema.ts`) → `generate-model-list.ts` → `modelList.ts` → `llm/models.ts` lookups (pure) + `llm/prices.ts` (`Price`, `costOf`). OpenRouter's live price range sits in `openrouter.ts`.
- **Model configs:** `model_configs` (0001, six enum CHECKs + combination rules) ↔ Worker `llmRoutes.ts` 52–460, 1247–1317 (row, `configProblem`, `unsupportedReason`, naming, `sameValues`, `modelOptions`, `SECRETS`, routes, Test, settings) ↔ web `api.ts` mirrors, `configForm.ts` (pure, tested), `NewModelConfig.tsx` (submit logic untested), `SettingsPage.tsx` configs part, `TestConfigDialog`/`testResult.ts`, `ConfigDialog`. Other readers of the row: pipeline.ts (aliased rebuild), projectFile.ts (import, `sameConfig`).
- **Money:** cost decided once, in `runCall` (unpriced NULL / provider-reported × fee / `costOf` / free 0; `vat_percent` then; `price_json`); read back in SQL: `COST_WITH_VAT` (vat.ts) in costs.ts, pipeline.ts (stage cost), `spentInLastDay` (cap); `UNKNOWN_COST` + `ZOMBIE_MS` (costs.ts; second `ZOMBIE_MS` in failures.ts); outcome CASE twice (costs.ts, failures.ts). Shown by web money.ts / pricing.ts / SettingsPage `amount`; run report sums. seedStats.ts is a third writer of `llm_calls` with its own prices.
- **Contracts:** (1) wire request/answer/place/stream (web ↔ Worker; only `CallEvent` shared); (2) request key (`keyedRequest`: drops bytes and cache marks; includes image recipe keys, so B's recipe changes re-key every call); (3) the provider port (`LlmRequest`/`LlmResponse`/`LlmError.kind`), every adapter the same; (4) `error_kind`/`status`/`http_status` written by the recorder, interpreted by costs, failures (Usage), cap; (5) schema ↔ answer type ↔ check (unpinned); (6) model list files ↔ schema.json ↔ `ProviderFile` ↔ TS unions; (7) config row ↔ CHECKs ↔ `configProblem` ↔ form's `missing()`; (8) "which stage owns a call" (cache, export, import, replay, deletion).

### P2: bugs that will hurt
- **C8. Recording a call is one long `try`: bookkeeping failures become provider failures, and an abort keeps another kind** [08 #7, #8].
