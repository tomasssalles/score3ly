# 04 worker: LLM routes and scripts

## apps/worker/src/llmRoutes.ts (+ llmRoutes.test.ts)

**What it does.** Five jobs in 1317 lines: (1) model configs: the row type, its conversion to the browser's shape (resolved model, price, "unsupported" reason), validation of a config body against the model list (`configProblem`), why a stored config is no longer supported, default naming, duplicate detection, conversion of hand-added configs to listed ones when a new list has their string (once per list, remembered in a module variable and a settings row); (2) the user's settings in D1 (defaults merged with stored JSON values, per-key validation); (3) the Hono routes: `/api/models`, `/api/secrets`, `/api/prices`, `/api/settings`, model-config CRUD (create/clone-replacing/rename/soft delete), price range (OpenRouter), a config's Test, marking a call unusable, and the stage's LLM call; (4) running a call: request validation, the request key (images by recipe key, cache marks dropped), item-level cache lookup in `llm_calls`, "images needed" round trip, spending-cap check, secrets from `env`, adapter creation, recording request/response as content-addressed canonical JSON in R2, status/cost/VAT bookkeeping, timeout and abort, streaming progress as SSE through a `TransformStream`; (5) a generic throttle.
Generic parts: **a throttle** (first value at once, latest at most every interval, flush/stop: `throttled`), **base64 to bytes** (`base64Bytes`), **content-addressed put of canonical JSON to R2** (`putJson`), **hand-written SSE framing** (`data: …\n\n`), **"first free name" numbering** (from names.ts), a sliding 24-hour sum (`spentInLastDay`), env-var listing (`secretNames`).

**Exports:** types `ModelConfig`, `ModelConfigRow`, `Settings`, `CallAnswer`, `ModelOptions`, `CallPlace`, `StreamEvent`; functions `resolvedModel` (row → model string, family, name), `modelGroupOf` (statistics grouping key/label), `unsupportedOf`, `providerCost` (reported cost × (1 + fee), rounded to 1e-6), `feeOf`, `toModelConfig`, `readSettings`, `configProblem`, `listKey` (hash of the list's ids and strings), `convertAddedConfigs`, message builders `deletedConfigMessage`, `unsupportedConfigMessage`, `deletedWhileRunningMessage`, `missingSecretMessage`, `spentInLastDay`, `modelOptions` (the config form's pickers), `devProviders`, `secretNames`, `llmRoutes`, `placeProblem`, `throttled`, `throttledProgress`; constants `NOT_SECRETS`, `TEST_REQUEST`, `PLACEHOLDER_ITEM`, `PROGRESS_INTERVAL_MS`.

**Imports:** `./vat.ts`, `./requestLog.ts`, `./names.ts`, `./llm/{openrouter,index,types,replay,timeouts,prices,adapters,models,modelList}.ts`; `@score3ly/core` (`CallEvent`, `canonicalJson`, `keyOf`, `sha256Hex`); `hono` (type). Platform: D1 (batch, prepared statements), R2 (`put` with `sha256`), `crypto.randomUUID`, `TransformStream`, `TextEncoder`, `atob`, `AbortSignal` (request's), `executionCtx.waitUntil`.

**Notable internal helpers:** `SECRETS` (adapter → accepted sets of secret fields), `bodyOf` (stored row → creation body, to re-validate), `unsupportedReason`, `pricingOf`, `configPrice`, `settingProblem`, `secretValues`, `requestProblem`, `base64Bytes`, `keyedRequest`, `recordedRequest`, `providerMessages`, `putJson`, `placeOf`, `progressEvent`, `sendCall`/`prepareCall`/`runCall`, `configName`, `sameValues`, `newConfigRow`, `insertConfig`.

## apps/worker/scripts/config.ts (+ config.test.ts)

**What it does.** Generates the two Wrangler configs from `wrangler.jsonc.template`: local-dev (template as is, with a "generated" header) and deploy (database id and the R2 bucket's jurisdiction spliced in by regex from `cloudflare.env`). Parses and formats `cloudflare.env` (a tiny **dotenv parser**: `NAME=value` lines, optional quotes). CLI entry with `import.meta.main`.

**Exports:** paths `workerDir`, `templatePath`, `localDevConfigPath`, `deployConfigPath`, `accountPath`; `JURISDICTIONS`, types `Jurisdiction`, `Account`; `parseAccount`, `formatAccount`, `withAccount` (text substitution, returns error when not found), `writeLocalDevConfig`, `writeDeployConfig` (throws).

**Imports:** `node:fs`, `node:path`. No repo modules.

**Notable internal helpers:** `templateBody` (strips the template's leading comment), the UUID regex `ID`.

**Findings**
- 27: `BUCKET = "score3ly-pdfs"` also defined in `setup-cloudflare.ts:161`; export it. **certain**
- 41-53: hand-written dotenv parsing; Node 22 has `util.parseEnv`. **check**
- 94-96: an unknown argument is reported only after `writeLocalDevConfig()` already ran; validate first. **certain**
- 65-74: config edited by regex on JSONC text (depends on the template's formatting, e.g. the bucket binding being one `{…}` without nested braces); acceptable for a template we own, guarded by the test. **check**

## apps/worker/scripts/callPlaces.ts (+ callPlaces.test.ts)

**What it does.** One-time migration logic: fills `item`/`round` on old `llm_calls` with placeholders. Round = number of assistant messages in the stored request + 1; item from outputs naming the call, else from other calls whose first message (images by recipe key, canonical JSON) matches; config Tests get `""`/1; unplaceable calls listed with reasons. Updates batched by 50.

**Exports:** `fillCallPlaces(db, bucket, log)`, types `Unplaced`, `Filled`.

**Imports:** `@score3ly/core` (`canonicalJson`). Platform: D1, R2.

**Notable internal helpers:** `firstMessageKey` (a message with images reduced to recipe keys, canonical JSON): the same normalization as `keyedRequest` in `llmRoutes.ts:510-518`, on the recorded shape. **check**

**Findings**
- 16: `PLACEHOLDER_ITEM` redefined; `llmRoutes.ts` exports it (scripts already import from `../src`). **certain**
- 47 + 78: a stored request with no messages is skipped like a missing one, then reported as "its stored request is missing", which is wrong for that case. **certain** (edge)
- 98: "D1 takes at most so many statements per batch": the limit isn't named; 50 is a guess. **check**
- 40-49: fetches every call's request sequentially (not only the ones to fill), needed for `byFirst`; fine for a one-time script. no finding.
- Once the script has run on the owner's databases the file (and fill-call-places.ts, its test, the npm script) is removable; overview says it is one-time. **check**

**Tests:** one scenario covering Test calls, `layout` rounds, a retry with other bytes, deleted project's call named by an output, unplaceable calls, idempotence. 131: same migrations-applying code as llmRoutes.test.ts (**certain**, see above). Gaps: "outputs of different items" and "requests like it belong to different items" reasons not exercised.
