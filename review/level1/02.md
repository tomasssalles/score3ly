## index.ts

- **Findings:** none.

## lensForm.ts (+ lensForm.test.ts)
- **What it does:** converts the lens between code's form (nulls, `class` + `kind`, `ending` object or null) and the model's form (no nullables: `""` and `-1` sentinels, merged `"new-normal"` class, `ending` enum + `endingLabel`), both ways. Generic part: "replace `""` with null on listed keys" and the reverse (`orNull`/`orEmpty`), "map if array else pass through" (`each`).
- **Exports:** `STRETCH_CLASS_VALUES`, `ENDING_VALUES`, `RIGHT_BAR_LINES`, `GROUP_SYMBOL_VALUES` (enums for the schemas); `orNull`; `staffFromModel`, `groupFromModel`, `voiceFromModel`, `stretchFromModel`, `issueFromModel`, `lensFromExtract` (model → lens); `staffForModel`, `groupForModel`, `voiceForModel`, `stretchForModel` (lens → model).
- **Imports:** none (no repo modules, no packages).
- **Notable internal helpers:** `record` (plain-object guard), `each`, `orEmpty`, `ENDINGS` table.
- **Findings:**
  - 11–14: enum constants duplicate notation's `BAR_LINES`, `GROUP_SYMBOLS`; `STRETCH_CLASS_VALUES` restates `STRETCH_CLASSES`/`MEASURE_KINDS` (lens.ts 12–15). Certain.
  - 18: `each` is redefined in applyReview.ts 182. Certain.
  - 34–40 vs 96: the ending table is written twice, once as `ENDINGS` and once inverted by hand in `stretchForModel`'s nested ternary. Certain (minor).
  - 61: an `endingLabel` given with `ending: "none"` is dropped silently. Check (probably intended).
  - 104: `(changes as Obj[]).map` throws if a stretch (or patch, per the comment at 91) lacks `changes`; the other fields are guarded. Check callers.
  - 98–110: `stretch` and `rightBarLine` are always emitted, as `undefined` when absent. Certain (harmless with JSON.stringify).
- **Tests:** round trip of every ending and class, staff round trip. The third test (52) checks review's and apply_review's schemas, which have no test files of their own (misplaced). `issueFromModel`/`lensFromExtract` are tested in extract.test.ts instead; `groupForModel`/`voiceForModel` only indirectly.

## layout.ts (+ layout.test.ts)
- **What it does:** `layout`'s prompt texts (system, first round, per-round check text), its JSON schema, and the check of the answer: fields present, boxes in [0,1] and non-empty, bar lines numbers inside their box with a tolerance, sorted.
- **Exports:** `LAYOUT_PROMPT_VERSION`, `LAYOUT_ROUNDS`, `LAYOUT_MAX_OUTPUT_TOKENS`, `LAYOUT_SYSTEM`, `LAYOUT_FIRST`, `layoutCheck(round)`, `LAYOUT_SCHEMA`, types `LayoutBox`, `LayoutSystem`, `LayoutAnswer`, `checkLayoutAnswer`.
- **Imports:** none.
- **Notable internal helpers:** `number(description)` (schema builder), `BAR_LINE_TOLERANCE`.
- **Findings:**
  - 34: `number(...)` is one more schema helper copy (see package-wide). Certain.
  - 68: `LayoutBox` = notation `Box` = imaging `Box`. Certain.
  - 77–101: shape validated by hand instead of with the schema (`shapeProblem` in analyze.ts validates against the schema itself). Check.
  - 84–86: a `null` entry in `systems` throws a TypeError (`s.left` on null) instead of returning a problem. Certain (unlikely with constrained output).
  - 96: bar lines up to 0.02 outside the box are kept unclamped, so they can lie outside the box or outside [0,1] (no 0–1 check on bar lines). Check what consumers do.
  - 95: duplicate bar lines, or ones at the box's edges, are not refused. Check.
  - 100: a non-string `note` silently becomes `""`, while every other wrong field is refused. Certain (minor).
- **Tests:** good answer and sorting, out-of-page/inverted boxes, bar line outside/just past box, last-round wording, prompt wording. Gaps: null entries, bar lines outside [0,1] within tolerance.

## analyze.ts (+ analyze.test.ts)
- **What it does:** `analyze`'s prompts (shared text, per-page, whole-score), schemas, and the conversion between the model's flat answer (one metadata list with categories, one observations list with kinds) and code's nested lists, both ways; ids for a page's items (`p7-3`); a generic JSON-Schema-subset validator (`shapeProblem`: anyOf, enum, object, array, string, integer, boolean, null); a normalizer that zeroes `number` of start/end places; semantic checks (places exist on the right page, staff k/n valid and consistent with reported staff counts, corrections/removals/additions name existing ids/pages, list-moving corrections become removal + addition).
- **Exports:** `ANALYZE_PROMPT_VERSION`, `ANALYZE_PAGE_MAX_OUTPUT_TOKENS`, `ANALYZE_SCORE_MAX_OUTPUT_TOKENS`, `CONFIDENCES`/`Confidence`, `TITLE_TYPES`, `ROLES`/`Role`, `SPECIAL_BAR_LINES`, `CHANGE_KINDS`, `TEXT_FIELDS`/`TextField`, `Metadata`, `PageMetadata`, `ScoreMetadata`, `PLACE_KINDS`/`PlaceKind`/`Place`, `BAR_LINE_PLACES`, `Staff`, item types (`TextItem`, `SystemItem`, `ChangeItem`, `OttavaItem`, `EndingItem`, `BarLineItem`, `DirectionItem`, `RecurringItem`), `PageObservations`, `PageList`, `PAGE_LISTS`, `ScoreObservations`, `SCORE_LISTS`, `PageAnswer`, `ScoreAnswer`, `withIds`, `ANALYZE_PAGE_SYSTEM`, `analyzePageText`, `ANALYZE_SCORE_SYSTEM`, `ANALYZE_SCORE_TEXT`, `METADATA_CATEGORIES`/`MetadataCategory`, `FlatMetadataItem`, `ObservationKind`/`OBSERVATION_KINDS`, `FlatObservation`, `FlatPageObservations`, `SCORE_KINDS`, `FlatScoreItem`, `flatMetadata`, `nestedMetadata`, `flatObservations`, `nestedObservation`, `nestedObservations`, `ANALYZE_PAGE_SCHEMA`, `ANALYZE_SCORE_SCHEMA`, `FlatPageAnswer`, `FlatScoreAnswer`, `AnalyzeContext`, `StavesOf`, `stavesProblem` (used by apps/web), `checkPageAnswer`, `checkScoreAnswer`.
- **Imports:** none.
- **Notable internal helpers:** `keyOfValue` (reverse lookup in a map, 247), `shapeProblem` (556, generic JSON-Schema validator), `normalized` (deep map, 593), `placeProblem`, `staffProblem`, `observationsProblem`, `metadataProblem`, `nestedScore`, `placeName`, schema builders 348–359.
- **Findings:**
  - 556–590: `shapeProblem` is a generic JSON-Schema validator, duplicating `schemaProblems` in apps/worker/src/llm/jsonSchema.ts; a candidate for one shared module (or a small package). Check.
  - 563–569: `shapeProblem` ignores `additionalProperties: false`, so unknown keys pass and are carried by `...rest` into stored items (`nestedMetadata` 268, `nestedObservation` 303, `checkScoreAnswer` 654). Check.
  - 348–359: `str`, `int`, `object`, `described`, `nullable` duplicate extract.ts/review.ts/applyReview.ts. Certain.
  - 251 and 282: the same local `type Any` declared twice. Certain (minor).
  - 247: `keyOfValue` does a linear reverse lookup and casts `undefined` to a key when not found; inverted maps built once would do. Check (minor).
  - 19: `SPECIAL_BAR_LINES` calls it `"startEndRepeat"`, the lens `"bothRepeats"` (lens.ts 14): two names for the same bar line across stages. Check.
  - 650–674: the same id corrected twice, or both corrected and removed, isn't refused. Check.
  - 501/503: an ottava's or ending's start after its end isn't checked. Check (minor).
  - 465–466: double blank line. Certain (cosmetic).
  - The file is 700 lines doing three jobs: prompt texts, flat↔nested conversion, schema validation and semantic checks; `shapeProblem` at least is generic. Check.
- **Tests:** thorough on checks (places, staves, shape, kinds' needs, metadata pieces, ids, corrections/removals/additions, list-moving corrections, score items, schema strictness). Gaps: recurring material with a bad place (697), duplicate/conflicting corrections, `analyzePageText`, extra keys in the answer.

## extract.ts (+ extract.test.ts)
- **What it does:** `extract`'s prompt: the symbolic format's description (`MUSIC`, its token lists generated from the parser's constants so the two can't drift), the recap of LilyPond pitfalls with wrong/right examples (`LENS_PITFALLS`, `lensRecap(writes)`), the system prompt, the request text, image labels, and the lens schema parts shared with `review` and `apply_review` (`LENS_SCHEMA_PARTS`) plus `EXTRACT_SCHEMA`.
- **Exports:** `EXTRACT_PROMPT_VERSION`, `EXTRACT_MAX_OUTPUT_TOKENS`, `extractImageLabels`, `MUSIC`, `LENS_PITFALLS`, `lensRecap`, `EXTRACT_SYSTEM`, `extractText`, `described`, `LENS_SCHEMA_PARTS`, `EXTRACT_SCHEMA`.
- **Imports:** ./lensForm.ts (enum constants); `@score3ly/notation/symbolic` (token lists: ACCIDENTALS, ARTICULATIONS, CLEFS, …).
- **Notable internal helpers:** `cmd`/`cmds` (format `\name` lists), `code`, `enumOf`, `FOUR_EDGES`, schema builders 200–214.
- **Findings:**
  - 200–214: schema builders duplicated (package-wide note). Certain.
  - 216: `FOUR_EDGES` restates `Box`; 282: `["reading","format"]` restates notation's `ISSUE_CLASSES`. Certain.
  - 48–137, 219–287: `MUSIC`, `lensRecap` and `LENS_SCHEMA_PARTS` are shared by three stages but live in extract.ts, so review.ts and applyReview.ts import "extract"; a shared module (e.g. with lensForm.ts) would say what they are. Check.
  - 197: `extractText` pretty-prints the request (`JSON.stringify(request, null, 1)`), review/applyReview send compact JSON. Check whether intended.
- **Tests:** drift between prompt and parser both ways, the prompt's examples parse, pitfalls' wrong/right parse as expected, no nullable in the schema, `lensFromExtract` conversion (belongs to lensForm.ts). Gap: `extractImageLabels`.
