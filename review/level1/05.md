# 05 worker: LLM providers and models

## apps/worker/src/llm/index.ts
- **What it does:** the factory of LLM adapters. `createProvider` switches on an adapter id (`ProviderConfig`, a discriminated union of each adapter's credentials) and builds the adapter; `createAdapter` translates a stored config's (provider, family, region, project, secrets by field) into a `ProviderConfig` via `adapterFor`, then calls `createProvider`. Also `bedrockModel`: prefixes a Bedrock model id with the routing ("global.", "eu.", …). Re-exports everything of `types.ts`.
- **Exports:** `ProviderConfig`, `createProvider`, `AdapterSettings`, `createAdapter`, `bedrockModel`, and `export *` from `types.ts`.
- **Imports:** `./anthropic.ts`, `./fake.ts`, `./google.ts`, `./openrouter.ts`, `./types.ts`, `./adapters.ts`, types from `./models.ts`. No packages.
- **Findings:**
  - L14–21, L52–64, adapters.ts: two naming schemes for the same providers (`Provider` "bedrock"/"ai-studio"/"vertex" in models.ts vs `ProviderId` "anthropic-bedrock"/"google"/"google-vertex" in types.ts), so every config goes through two translations (`adapterFor`, then the `ProviderConfig` switch). adapters.ts's own comment calls the ids "old". **certain** (design debt for the plan).
  - L57–63: `config as ProviderConfig` and `secrets.apiKey!` hide a missing secret: an absent key becomes `apiKey: undefined` typed as string, and fails later with the SDK's own message (OpenRouter checks it, Anthropic/Google don't). **check**
  - L59: Bedrock spreads every secret field into the options after `region`; a secret field named `region` (or any other option) would override it. Harmless today. **check**
  - L66–73: `bedrockModel` is Bedrock-specific (its inverse, `bedrockNames`, is in anthropic.ts); index.ts is otherwise only the factory. **check** (placement)
- **Tests:** in bedrock.test.ts (anthropic.ts's section): `bedrockModel`, `createAdapter` for supported and unsupported pairs.
