# Level 2, group 11: the model list and prices

Files: apps/worker/src/llm/models.ts (+test), prices.ts, generateModelList.ts (+test), apps/worker/scripts/generate-model-list.ts, apps/worker/model-list/gather/{anthropic,bedrock,ai-studio,vertex,openrouter}.ts; read beside them: model-list/schema.json, the provider JSON files' heads, gather/README.md, the consumers in llmRoutes.ts (`unsupportedReason`, `configProblem`, `convertAddedConfigs`, `modelOptions`, `prepareCall`), web api.ts/configForm.ts/pricing.ts/about.ts for the contract only.

## Map

- **Step 1, gather (Node scripts, by hand before a release):** each `gather/<provider>.ts` downloads public pages into `downloads/` (ignored), cuts committed excerpts into `sources/<provider>/`, parses them with the hand-kept `claude-models.json` / `gemini-models.json`, writes `model-list/<provider>.json`. `fake.json`, `fake-dev.json` are written by hand. Nothing imported from `src/`; nothing typechecked or tested (finding 3).
- **The contract of step 1 → 2:** `model-list/schema.json` (checked by `jsonSchema.ts`'s `schemaProblems`) and the TS type `ProviderFile` (generateModelList.ts 10), which restate each other; the schema's enums restate `Provider`, `Family`, `Effort`, `Routing` (finding 14).
- **Step 2, generate:** `scripts/generate-model-list.ts` validates the files, imports the previous `modelList.ts` for retired models, calls `buildModelList` (join by id, retire what vanished, `listProblems`), writes `src/llm/modelList.ts` via `modelListModule`, prints `listChanges`. `--check` compares. generateModelList.test.ts pins files → module (the drift test).
- **Lookups:** `models.ts`, pure, list as first argument: places, prices (`listedPrice`, `offered`, `placesOf`), `resolveModel`, `priceOfConfig`, `configBaseName`, `effortsOf`, `listProblems`; names (`PROVIDER_NAMES`, `FAMILY_NAMES`, `ACCOUNT_NAMES`), `EFFORTS`, OpenRouter's accounts. `prices.ts`: `Price`, `costOf`.
- **Consumers:** llmRoutes.ts only, on the Worker (configs' validity, pricing, the pickers' `modelOptions`, the call's price and Bedrock geography, `/api/prices`). The web gets the list only through `/api/models` and `/api/prices`, and restates its types (group 12).

## Findings

1. **The list's date is the fake files' date, forever.** `asOf` is the oldest `collectedAt` of all files (generateModelList.ts 73), and `fake.json` / `fake-dev.json` are hand-written with `"collectedAt": "2026-11-05"`, older than every real gathering (11-06 to 11-08): `modelList.ts` has `asOf: "2026-11-05"` today, and will keep it after any later gathering until someone edits the fake files. It reaches the About page's "prices as of" and its stale warning (`pricesStale`, about.ts 30), and is stored with every priced call (`price_json.asOf`, llmRoutes.ts 1214). Fix: take the date from the gathered providers only (skip `fake`/`fake-dev`, or files with no `sources`); a test that `asOf` equals the oldest real file's date. **certain** (bug).
2. **A retired model keeps its old strings, and they block a hand-added config of the same model.** `buildModelList` keeps a vanished model as `{ ...old, retired: true }` with its `strings` (generateModelList.ts 70); `modelByString` (models.ts 125) doesn't skip retired entries. So `configProblem` refuses adding by hand a model the list retired ("The app no longer supports X on Y", llmRoutes.ts 320–324), and `convertAddedConfigs` (llmRoutes.ts 413) turns an existing hand-added config into the retired id on the next list, which then is unsupported (no places, `unsupportedReason` 184). A model that leaves only one provider's file loses that string instead (it isn't retired), so there it *can* be added by hand: two behaviours for the same situation. The hand-added model is the user's way to keep using a model the list dropped but the provider still serves (e.g. Bedrock's cards that changed format, README "Bedrock"). Fix options: `modelByString` skips retired entries; or retired entries keep no strings (they exist for their names, docs/llm.md "a model that leaves the list stays … so that its name still shows"). **certain** (mechanism), **check** (intended? ask the owner).
3. **The gather scripts are outside every check.** `tsconfig.json` includes `src` and `scripts`, not `model-list/gather`; no test runs them; they build their output as untyped objects (`Record<string, unknown>[]`, object literals) although `ProviderFile` exists. The only check is downstream (the schema, at step 2). Nothing pins the committed excerpts to the committed provider JSON either (a hand edit of `bedrock.json`, or a parser change not re-run, passes every test), while step 2 has a drift test. Fix: add `model-list/gather` to the tsconfig, `satisfies ProviderFile` on each `file`, and a test (or a `--check` per script, like generate-model-list's) that re-parses the committed excerpts and compares with the committed JSON; the parse is deterministic given the excerpt's fetched date. **certain**.
4. **One skeleton written five times** (level 1, confirmed): paths per provider (`here/downloads/sources/output/today`), the download loop (fetch, `ok`, write, log; bedrock's 404 skip, vertex's `Accept-Language`), the excerpt's header (two formats: a `# url` / `# fetched …` text header in anthropic, bedrock, openrouter; a JSON head line in ai-studio, vertex, whose `header`/`writeJsonl`/`readJsonl` exist only in vertex.ts and are inlined in ai-studio.ts 95–102, 135–137 and bedrock.ts 146–149, 206), problems → `exit(1)`, the file's frame (`$schema`, `provider`, `collectedAt`, `sources`, models with `efforts`/`thinking`), `writeFileSync(JSON.stringify(…, null, 2) + "\n")`, the `--download` switch. Also the hand-kept files' types restated: `Known` for claude-models.json in anthropic.ts 30, bedrock.ts 35, inline in openrouter.ts 34; for gemini-models.json in ai-studio.ts 31, vertex.ts 35 (`KnownGemini`), inline in openrouter.ts 35. One `gather/common.ts` (Node only): `paths(provider)`, `download(entries, init)`, `writeExcerpt`/`readExcerpt` (the JSON-lines form for every provider), `claudeModels()`/`geminiModels()` typed once (efforts as `Effort[]`), `writeProviderFile(file: ProviderFile)`, `fail(problems)`; plus finding 6–8's helpers. **certain**.
5. **A missing fetched date becomes today, silently,** in the three text-header scripts (anthropic.ts 90, bedrock.ts 156, openrouter.ts 68: `?? today`), where ai-studio and vertex fail on a bad head. Re-parsing an excerpt whose header was lost stamps today on old prices, and so moves `asOf` (once finding 1 is fixed). Folds into 4 (one excerpt format, which throws). **certain** (minor).
6. **Two HTML-table scrapers** (level 1, confirmed): bedrock.ts 68–75 (`cellText`, `rows`: `<tr>` without attributes, only `&nbsp;` decoded) and vertex.ts 43–69 (`decode`, `text`, `tables`). The entity doubt is dropped: what bedrock reads through `cellText` (region codes, `bedrock-runtime`, model IDs) holds no entities. One `tables(html)` with vertex's decoding in common.ts would serve both. **certain** (duplication, low value: scrapers are expected to change per release).
7. **Three dollar parsers** (anthropic.ts 81 "$x / MTok", ai-studio.ts 118 "$x tail", vertex.ts 188 "$x" exactly), confirmed; the formats differ, so one shared `leadingUsd(text): { usd, rest }` saves little. Plus bedrock's `Number(pricePerUnit.USD)` and openrouter.ts's `perMillion` (adapter, 268). **certain** (minor).
8. **Dates "December 1, 2026" parsed two ways:** `isoDay` with a month table (ai-studio.ts 42–50) and `Date.parse` (vertex.ts 205–207). Both Node only; `Date.parse` of that form is V8's lenient parse, and only compared with itself (local midnight), so no bug. One `isoDay` in common.ts. The different policies (valid today vs latest) are decided and documented (gather/README.md) → no finding. **certain** (dup, minor).
9. **`onlyOn` handled asymmetrically:** vertex.ts 202 silently skips a model marked `onlyOn: "ai-studio"` even when the locations page lists it; ai-studio.ts 148 lists a model marked `onlyOn: "vertex"` if its page has it. Neither reports the marker as stale. Report a stale `onlyOn` as a problem in both. **check** (minor).
10. **Dead lookups in models.ts:** `modelString` (119) and `modelsOf` (147) are used only by models.test.ts; the pickers moved to the web, where configForm.ts has its own `modelsOf` over `ModelOptions`. Level 1's "all used outside" was wrong for these two. `offered` and `listedPrice` (130, 135) share one predicate: one `priceEntry(list, model, provider, place): PriceEntry | undefined` serves both. **certain**.
11. **`modelOptions` rebuilds the lookups** (llmRoutes.ts 640–651): the provider's places are `placesOfProvider` plus `geography`, the model's places are `placesOf` plus `price` (filtering `list.prices` again). `placesOfProvider` returning `geography` (it is the `RegionEntry`'s) and a `pricesOf(list, model, provider)` would make them one. The same geography lookup again in `prepareCall` (llmRoutes.ts 1123). **certain** (minor).
12. **`priceKey` = `listProblems`'s `where`** (generateModelList.ts 94 vs models.ts 274; provider id vs `PROVIDER_NAMES`), and `regionKey` (generateModelList.ts 116) ≈ the region `where` (models.ts 261). One `priceWhere(p, name = PROVIDER_NAMES)` in models.ts. **certain** (minor).
13. **generate-model-list.ts 36–40: any failure to import the previous list counts as "no previous list".** A syntax error in `modelList.ts`, or Node refusing an absolute Windows path as an ESM specifier (should be `pathToFileURL(modulePath).href`), and the write mode overwrites `modelList.ts` without its retired models (finding 2's names lost for old configs and calls), printing only "every model is new". Catch only `ERR_MODULE_NOT_FOUND`. **certain** (the catch-all); Windows **check** (only the owner runs it).
14. **The schema restates the TS unions:** `provider`, `family`, `efforts`, `routing` enums in schema.json, against `PROVIDERS`, `Family`, `EFFORTS`, `Routing`; and `ProviderFile` restates the schema. Nothing pins them (a value in the schema the TS lacks passes `content as ProviderFile`). A test comparing the schema's enums with `PROVIDERS` and `EFFORTS`, or the schema generated from the types (group 10 #6's options). **check** (minor).
15. **`listChanges` and `buildModelList` see less than they could:** no change line for a model's name, efforts or thinking (an efforts change can make configs unsupported); thinking taken from whichever file says it, with no disagreement check as efforts have (generateModelList.ts 50–54). **check** (minor; all come from one hand-kept file today).
16. **`/api/prices` returns `mock`; the web's `fetchPrices` types only `asOf`** (api.ts 582), so the About page can't say the list is a stand-in. `modelOptions` carries `mock` too. **check** (whether the mock still matters: no file is mock now).
17. **`jsonSchema.ts` sits in `src/llm/`** (the Worker's source) but serves only the Node script and its test; move it beside the script, or replace it with group 10 #2's shared validator. **certain** (placement).
18. **Tests:** models.test.ts 121 (`listProblems(MODEL_LIST)` is `[]`) repeats the drift test, which already runs `listProblems` on the built list that equals `MODEL_LIST`; models.test.ts 286–291 (35 Bedrock regions, eu-central-1's entry) and 270–273 assert facts of the data, and break on each refresh. Keep those on the small list `LIST`. `priceOfConfig`'s "provider" kind is untested (level 1). **certain**.

## Patterns

- **A script per provider, each written by copying the last** (4, 5, 6, 7, 8, and the `Known` types): count 6. Cause: each provider gathered in its own session, on a different page format, so the shared part (downloads, excerpts, the file's frame) was never extracted; the excerpt format even changed halfway (text header → JSON lines) without the earlier scripts following.
- **Code outside the checks** (3, 13, 17): count 3. Cause: Node scripts run by hand were placed outside the tsconfig's `include` and the test glob, so neither the typecheck nor the tests saw them; error handling written for the happy first run (catch-all import).
- **A rule written for the real data that the hand-made data breaks** (1): count 1. Cause: "the list's date is the oldest file's" was decided before the fake files joined the list; nothing tested the date.
- **A state kept for one purpose, read by another** (2): count 1. Cause: retired entries were kept for their names; `modelByString`, written for converting added configs, didn't consider them.
- **Lookups left behind after their caller moved** (10, 11): count 2. Cause: the pickers moved to the web over `ModelOptions`, `modelOptions` was written inline instead of with the lookups, and the old ones stayed, kept alive by their tests.
- **Restated enums and types across a format boundary** (14, 16, and the web's copies): count 3. Cause: schema.json written by hand beside the TS type; the web cannot import the Worker, so the API types were copied.
- **Data-coupled tests** (18): count 1. Cause: asserting facts of the first real gathering as a sanity check, in a unit test.
