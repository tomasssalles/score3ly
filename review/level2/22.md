## Patterns
- **A UI part rebuilt by hand instead of using (or extending) the existing one** (dialog shell 8, pickers 5 + a second component, "i" toggle 5, tabs 2, filter section 2, out-set toggle 3, click-outside 2, matchMedia 2, lazy load 2, storage 4, project option 2, inline SVG icons 2): 12 kinds, ~40 copies. Cause: each screen written in its own session, starting from the nearest similar screen and copying it; the style guide says "one component" but names it only for a few (`DropdownMenu`, `CheckList`, `StatHead`, `TimeChart`), and where it names none the copy wins. Candidate rule: before building a UI part, grep for the class name of the similar one; when a second copy appears, extract the component.
- **A generic helper written inline at every use** (`plural` ~30, three local lambdas, one file twice): 1 kind. Cause: too small to look for; no formatting module existed to put it in.
- **A shared helper placed in the first file that needed it** (`useRemembered` in ExtractionView, `Picker` in statsParts used by Settings, `FinishedProjectsFilter` in a misnamed file): 3. Cause: as group 21: written for one screen, imported later instead of moved.
- **The CSS drifting from the guide** (opacity 4 values, sizes, radii, an end ellipsis, a second spinner): 5. Cause: values typed per rule with no tokens for them; the guide's numbers aren't enforced by a test, as the colours are (colors.test.ts).
- **A lint-like test that silently tests nothing** (finding 1; errorText's misses, group 07 #12): 2 in the app. Cause: a regex over source is the cheap check, and a negative assertion passes when the parser finds nothing; no test checks that its target was found.
- **Stale text** (statsParts' header, icons' double comments, `.settings-section-head h3`, the `.stats-tabs` comment, orphaned CSS comments): 5. Cause: code moved or reused without its comment being reread.
