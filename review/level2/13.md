# Level 2, group 13: costs and money

Files: apps/worker/src/costs.ts, vat.ts, migrations/0003_vat.sql, llmRoutes.ts (the cost at call time, `providerCost`, `spentInLastDay`, `prepareCall`'s cap, the settings' cap and VAT, the Test's cap text); apps/web/src/costs.ts (the parts about money), money.ts, pricing.ts, runReport.ts, SettingsPage.tsx (`VatRate`, `SpendingCap`, `amount`), StatsPage.tsx (`SpendingCap`), StageDetails.tsx (the stage's cost); scripts/seedStats.ts (its prices and costs). Read beside them: failures.ts (`ZOMBIE_MS`, the bucket), pipeline.ts 287 (a stage's cost), llm/prices.ts, llm/timeouts.ts, llm/types.ts 121–131 (524), modelList.ts (prices for the seed), docs/llm.md "Calling the providers", "VAT", "Spending cap".

## Map

- **Computing a cost (Worker, at the call's end, `runCall` 1181–1213):** `priceOfConfig` → unpriced: NULL; priced by the provider: `providerCost` (reported × (1 + fee), rounded to 1e-6); listed or borrowed price: `costOf` (prices.ts, tokens × price, rounded to 1e-6); free: 0. `vat_percent` read from the settings then. `price_json` keeps the price (with the list's date, `borrowedFrom`) or the reported cost, fee and account. A failed call: no tokens, cost NULL, `vat_percent` 0, `http_status`/`error_kind` kept (they decide "of unknown cost" later). Cached answers make no row.
- **With VAT, everywhere it is read:** `COST_WITH_VAT` (vat.ts, SQL `c.cost_usd * (1 + c.vat_percent / 100.0)`) in costs.ts (points, tests, per-project sums), pipeline.ts 287 (a stage's `costUsd`), `spentInLastDay` (llmRoutes 575); `withVat` only for the call's answer (1221). Migration 0003: `vat_percent REAL NOT NULL DEFAULT 0`. Import keeps each call's rate (projectFile.ts 349).
- **The cap:** setting `spendingCapUsd` (`settingProblem`: number > 0; default $1). `spentInLastDay`: known costs with VAT of non-free configs' calls started in the last 24 h, Test calls and deleted projects included. `prepareCall` refuses a priced or provider-priced call when spent ≥ cap (OpenRouter `:free` models excepted), 429 `spending_cap`; the Test strips the sentence about calls already paid for.
- **"Of unknown cost":** only `UNKNOWN_COST` (costs.ts 29), SQL, with the `ZOMBIE_MS` cut-off bound as `?`.
- **`GET /api/costs` → web `CostData` (api.ts 380) → web costs.ts `costView`/`averagePerPage` → StatsPage.** Points carry an `outcome` string (Worker CASE, costs.ts 45) that the web labels (`STATUSES`, costs.ts 186).
- **Shown:** money.ts `dollars` (two decimals, "<$0.01"): Costs tab, stage details, Test result. pricing.ts `dollars` (per-million prices, "$4", "$0.001"), `withFee`, `rangeText`, `pricesText`: settings cards. SettingsPage `amount` (the cap's field). Worker: `spendingCapUsd.toFixed(2)` in the cap's refusal.
- **The run report** (runReport.ts): each pipeline stage's `costUsd` as the Worker summed it (with VAT), total summed and rounded to 1e-6 in the browser.
- **seedStats.ts:** its own price table, cost formula, cap simulation, written as SQL for the statistics' mock data.

## Findings

1. **A call cut off by Cloudflare (524) is counted as not billed, against its own comment** — costs.ts 29: `UNKNOWN_COST`'s "no tokens" branch requires `http_status IS NULL OR http_status < 400`; `runCall` records a 524 with `http_status = 524` and kind `timeout` (llmRoutes 1220–1238, test llmRoutes.test.ts 1002), while its comment (1226) and `cloudflareTimeoutMessage` say the provider "may have finished and billed" it. So such calls vanish from the costs view's "calls of unknown cost" (and are counted as plain failures elsewhere, group 14). The 524 is the one HTTP status that isn't the provider's: either record it without `http_status` (it isn't the provider's answer) or make the rule `http_status >= 400 AND http_status <> 524`. **certain**; no test of the costs view with a 524 row.
2. **A call's "unknown cost" is judged by the config's pricing now, not at call time** — costs.ts 29 first branch: `m.pricing_kind = 'unpriced' AND c.input_tokens IS NOT NULL`. `convertAddedConfigs` (llmRoutes 418) turns an unpriced config into `list` when a new model list has its model; its old calls (tokens known, `cost_usd` NULL) then match no branch and drop out of the count silently (the docs promise the costs view counts them, "the total may be far higher"). Since a listed price always gives a cost when tokens are known, the first two branches are just `c.input_tokens IS NOT NULL AND c.cost_usd IS NULL` (any non-free config), which reads the call, not the config, and is shorter. Same family of fragility: every query filters `m.pricing_kind <> 'free'` on the config's current kind (fine today: `free` never changes). **certain**; untested.
3. **`ZOMBIE_MS` (15 minutes) contradicts the timeouts built since (60 minutes)** — costs.ts 22–23 and failures.ts 11 (two copies, level 1): "a call still running after this long will never answer", but `LLM_TIMEOUT_MINUTES` (llm/timeouts.ts) lets a stage's call run 60 minutes, and the Worker records its real end then. A call 15–60 minutes into a long thinking answer is shown as "of unknown cost" (and "interrupted" in Usage) while it runs, and moves when it ends. One constant, derived from the longest timeout (`llmTimeoutMs` max + a margin), in one module both import. **certain** (the stale assumption; whether the doc's "15 minutes" decision should follow the timeouts is the project owner's).
4. **A stage's cost and the run report can't tell "unknown" from "nothing", and under-report silently** — pipeline.ts 287: `SUM(COST_WITH_VAT)` over the stage's calls; SQL's SUM skips NULLs, so a stage with some stopped/timed-out/unpriced calls shows only the known part, an unpriced stage shows no cost at all (StageDetails 30 omits it), and the run report writes `costUsd: null` both for a computed stage and for an LLM stage of unknown cost; `totalCostUsd` (runReport 88) adds only the known ones and says nothing. A count of unknown-cost calls beside the sum (the same predicate as finding 2) would let the details say "$0.42 + 3 calls of unknown cost" and the report carry it. **certain** (the gap); what to show is a decision.
5. **Rounding: two kinds of number in one report** — runReport 88 rounds the total to 1e-6, but each stage's `costUsd` comes from SQL `cost × (1 + vat/100.0)` unrounded (e.g. 0.014161000000000001); `withVat` doesn't round either. Rounding to micro-dollars is written in `costOf` (prices.ts 15), `providerCost` (llmRoutes 229), runReport 88, seedStats 163 (and openrouter.ts 268 for prices). One `roundUsd` beside `costOf` for the Worker; the report rounds every stage like the total (or the Worker rounds the SQL sum). **certain** (minor).
6. **The Worker's money code is scattered over the 1300-line llmRoutes.ts, and costs/failures depend on it** — `providerCost`, `feeOf`, `spentInLastDay`, `DAY_MS`, the cap check in `prepareCall`, `readSettings`'s cap and VAT, while vat.ts holds three small pieces and costs.ts holds `UNKNOWN_COST` and `BUCKET_SECONDS` (which failures.ts imports from costs.ts). One `spending.ts` (or vat.ts grown): `COST_WITH_VAT`, `withVat`, `isVatPercent`, `providerCost`, `spentInLastDay`, `capRefusal` (the check and its message, with the Test's variant as a flag instead of `.replace`, group 12 #12), `UNKNOWN_COST`, `ZOMBIE_MS`, and a `quarterSql(column)` for the bucket expression written four times (costs.ts 43/54/65, failures.ts 21). costs.ts and failures.ts would import it, not llmRoutes. **certain** (structure).
7. **Two classifications of a call's outcome, on both sides** — Worker costs.ts 45 (`unexpected_model` → `wrong_model`, error → `unexpected_stop`, else status) and failures.ts 18–26 (running → `interrupted`, the four statuses, error without kind → `unexpected_stop`, else `error_kind`, so `unexpected_model` stays); web costs.ts 186 `STATUSES` ("Wrong model" under `wrong_model`) and usage.ts `REASONS` (under `unexpected_model`). The same call is "wrong_model" on one tab and "unexpected_model" on the other; `CostData.points`'s outcome is typed `string`. One outcome vocabulary (a type in core, with its labels in one web table), the costs view being failures' classification restricted to billed calls. **certain**; the Usage half is group 14's.
8. **Three dollar formatters, two named `dollars`** — money.ts 3 (amounts: "$4.00", "<$0.01"), pricing.ts 12 (per-million prices: "$4", "$0.001"), SettingsPage 657 `amount` (the cap's field text), plus the Worker's `toFixed(2)` in the cap's refusal (llmRoutes 1111; a cap of $0.004 reads "$0.00"). The two jobs (amounts vs prices) are real; rename pricing.ts's to `perMillion` and keep it private to pricing.ts (only used there), and `amount` is money.ts's job (an input's text). **certain** (level 1, confirmed).
9. **The settings' rules are written on both sides** — `VatRate` (SettingsPage 621: 0–100, two decimals) = `isVatPercent` (vat.ts 155); `SpendingCap` (`usd > 0`) = `settingProblem` (llmRoutes 291). The web can't import the Worker; `isVatPercent` and an `isCapUsd` belong in `@score3ly/core` with the `Settings` type (restated in api.ts 352, group 12 #8). The two components are one component twice (level 1: confirmed); and two components named `SpendingCap` (SettingsPage 661 the field, StatsPage 280 the meter) in one app. **certain** (minor).
10. **seedStats' prices have already drifted** — its own `PRICES` (seedStats 91–97, "as llm/prices.ts has them", but prices.ts holds no prices since the model list) price `OPUS_EU_*` (Bedrock, eu-central-1, geographic) at Opus's $4/$20, while the list has $4.40/$22 there; `claude-haiku-5-5` (HAIKU, 129) isn't in the list at all, so the seeded config shows unsupported. The script runs in Node with TS and already imports Worker code (`writeLocalDevConfig`): `priceOfConfig(MODEL_LIST, …)` and `costOf` would keep it true. It also never sets `vat_percent` nor a VAT setting, so the mock data never shows VAT. **certain**.
11. **The docs promise a mark the costs view doesn't have** — docs/llm.md 233: "the costs view marks the costs computed from a borrowed price as estimated from another model's"; nothing in costs.ts (Worker or web) or StatsPage reads `price_json.borrowedFrom` (grep "borrow": none), and no task in tasks.md mentions it. Also docs/llm.md 278 names "Migration 0012", which doesn't exist (0001–0004). **check** (for the docs review: unbuilt or dropped).
12. **The call answer's money fields aren't read where it is streamed** — `CallAnswer.costUsd`/`vatPercent` (llmRoutes 567–568) are sent with every stage call; the web's `LlmAnswer` (api.ts 505) has `costUsd` without `vatPercent` and no stage code reads either; only the Test (`TestResult.costUsd`) uses the cost. Wire drift of the kind group 08 #1 covers. **certain** (minor; folds into 08 #1).
13. **`counted` embeds `UNKNOWN_COST`'s `?`** (costs.ts 38, used at 75 and 85, each `.bind(zombie)`): correct today, easy to break; with finding 6's module, `UNKNOWN_COST` can take the cut-off as an ISO literal built in code, or `counted` become a CTE bound once. **certain** (minor, level 1's check confirmed).

## For level 3

- **The LLM path's component (groups 08, 09, 12, 13):** the recorder (`runCall`) is where a call's money is decided (cost, VAT, `http_status`, `error_kind`), and the statistics (`costs.ts`, `failures.ts`) re-derive meaning from those columns in SQL. The contract between them ("billed", "of unknown cost", "interrupted", the outcome) is nowhere written as code: it is three SQL predicates and two CASEs. A small module that owns both the recording vocabulary and the predicates (finding 6) is the component boundary; its tests should pin rows written by `runCall` (524, stop, timeout, unpriced converted) to what the views count.
- **Settings shared by both sides** (`Settings`, the cap's and VAT's rules) belong in `@score3ly/core` beside `RunMode` (groups 12, 13).
- **Mock data is a third writer of `llm_calls`** (seedStats.ts) besides the Worker and the importer: it should use the Worker's price lookup and cost function; group 24 for the rest of the script.
- **Group 14** should take finding 1 (524) and 3 (`ZOMBIE_MS`) for the Usage tab's "interrupted" too, and finding 7's half there.

## Patterns

- **A rule restated where a later feature changed its premise** (1, 2, 3): count 3. 524 handling, the conversion of added configs, and the 60-minute timeouts were each built after `UNKNOWN_COST`/`ZOMBIE_MS`, in other files, and nobody went back to the SQL that interprets the columns they write. Likely cause: the meaning of a stored column (`http_status`, `pricing_kind`, `status = 'running'`) lives in comments and docs, not in one piece of code that both the writer and the readers use, and no test feeds the writer's real rows to the readers.
- **A constant or small helper written again** (3 `ZOMBIE_MS`, 5 rounding ×4, 6 bucket SQL ×4, `DAY_MS` ×2, 8 formatters ×3, 9 validation ×2): count 6. Cause: the first copy was private to a route module (`costs.ts`, `llmRoutes.ts`), or on the other side of the web/Worker boundary with no shared package in use for it.
- **A copy of data that drifts** (10 seed prices; 11 a doc mark never built): count 2. Cause: mock data written by hand "as the code has it" at one moment, with a comment instead of an import.
- **Sums that hide what they leave out** (4, and 1–2 for the view): count 1 (design). Cause: SQL `SUM` skipping NULL made "unknown" disappear by default; the unknown-cost count was added for the costs view only.
- **Two vocabularies for one thing** (7 outcomes; two `SpendingCap`s; two `dollars`): count 3. Cause: tabs and screens written in different sessions, each naming what it needed.
