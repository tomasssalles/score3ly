# Level 2, group 09: Provider adapters

## Map
- **`llm/types.ts`**: the port. `LlmRequest` (model, system, messages of text/image parts with `cacheUpTo`, `maxOutputTokens?`, `effort?`, `adaptiveThinking?`, `jsonSchema?`), `LlmResponse` (provider, model, text, json/invalidJson/unexpectedModel, stop, usage, reportedCostUsd, servedBy, raw), `LlmUsage`, `LlmProgress`, `LlmError` (kind, status, `retryable`), `LlmProvider` (`id`, `send(request, signal, onProgress)`), `kindForStatus`, `cloudflareTimeoutMessage`, `withJson`.
- **`llm/adapters.ts`**: (Provider, Family) → old `ProviderId`. **`llm/index.ts`**: `createAdapter` (config + secret values → `ProviderConfig`) → `createProvider` (switch on `ProviderId`); `bedrockModel`.
- **Adapters:** `anthropic.ts` (`ClaudeProvider`, Anthropic API and Bedrock through Anthropic's SDKs, `bedrockNames`), `google.ts` (`GoogleProvider` and `VertexGeminiProvider`, REST `streamGenerateContent` by hand through `streamGemini`, `@google/genai` for types and two enums), `openrouter.ts` (`OpenRouterProvider` + `CompletionStream`, plain fetch; also the price-range lookup used by the cap and the form), `googleServiceAccount.ts` (JWT RS256 with WebCrypto, token cache per account).
- **`llm/timeouts.ts`**: per-step timeouts, `withTimeout` (outer signal + timer → plain abort, `timedOut()`).
- **Consumers:** only `llmRoutes.ts` `prepareCall` (`createAdapter`) and `runCall` (`send`, `withTimeout`, error → kind/message, `cloudflareTimeoutMessage`); `scripts/try-llm.ts` (`createProvider` with old ids). Google and OpenRouter read SSE with core's `readSse`.
- **Contracts:** (a) every adapter returns the same `LlmResponse` (usage without cache tokens in input, thinking in output; stop mapped to four values; json parsed only on `end`); (b) every failure is an `LlmError` whose `kind` the route records as `error_kind` (Usage tab, group 14) and whose `status` decides "not billed"; (c) abort and timeout arrive as a plain abort on `signal` and must come back as `aborted`; (d) constructors may throw `LlmError` (credentials) — the route has to catch it.

## Findings

1. **A bad Vertex key file fails as "HTTP 500", even in the config's Test** — `VertexGeminiProvider`'s constructor calls `parseServiceAccount` (google.ts 205), which throws `LlmError("auth", "The service account key isn't valid JSON." / "lacks its type, …")` (googleServiceAccount.ts 24, 28); it runs inside `createAdapter` in `prepareCall` (llmRoutes 1118), which neither route wraps in a try (llmRoutes 816 Test, 931 `/llm`). So the clear message is lost to Hono's plain 500 (group 07 #10), exactly where a user first checks a new key (Test), and no call is recorded. Group 07 #10 thought only a D1 failure reaches `prepareCall`; the adapters' constructors do too (Bedrock's credential check, anthropic.ts 85, and OpenRouter's, openrouter.ts 201, are unreachable today: `configProblem` fixes the secret fields, `secretValues` refuses empty values). Fix: `prepareCall` turns an `LlmError` from `createAdapter` into a refusal (`code: "bad_secret"`, 409), or the adapters parse lazily in `send` (then the error is recorded like any auth error). certain.

2. **Claude calls are retried by the SDK, the others never** — `anthropicProvider`/`bedrockClaudeProvider` take `maxRetries` but `createAdapter` never passes it (index.ts 26–28), so the SDK default 2 applies in production: on 408, 409, 429, every status ≥ 500 and connection errors, it sleeps (honouring `retry-after`) and resends, invisibly: one `llm_calls` row for up to three HTTP requests. Every test passes `maxRetries: 0`, so the production setting is untested. Worst case: a **524** (Cloudflare cut a call the provider may have billed, types.ts 116–122) is ≥ 500, so it is resent twice, each possibly billed, before `cloudflareTimeoutMessage` is shown once. Gemini and OpenRouter adapters have no retry; `LlmError.retryable` (types.ts 97) is read by nothing but tests (grep), so the app has no retry policy of its own. Decide one: `maxRetries: 0` in `createAdapter` (the stage's Retry is the policy, as for the other providers), or retries only for 429/529 for every adapter in one place. certain.

3. **`ProviderId` is a second naming scheme kept alive only by itself** — `LlmProvider.id` and `LlmResponse.provider` are read by no production code (grep: only the adapters' tests assert them); the route knows the config's provider. Yet each adapter sets and overrides them (anthropic.ts 55/136, google.ts 113/217, openrouter.ts 110, fake.ts 40, replay.ts 31), `adapters.ts` maps every pair to an "old provider id", and `createProvider` switches on it. Only `try-llm.ts` exposes the old ids to a person. Fix (with group 12): `createAdapter` switches on (Provider, Family) directly; drop `ProviderId`, `ProviderConfig`'s ids, `id`, `LlmResponse.provider`; `adapters.ts` becomes a set of supported pairs; `try-llm.ts` takes the app's provider names. Settles level 1's "two naming schemes" and group 08's hand-off. certain.

4. **The same failure gets a different kind on each provider** — a connection dropped mid-stream: Google `network` (TypeError, google.ts 170), OpenRouter `unreadable_response` (openrouter.ts 250), Claude whatever the SDK throws (`unreadable_response` or `network`). A programming error (a TypeError in `parseChunk`, `addProgress` or the route's `onProgress`) is recorded as `network` on Google. The AbortError test is written three times in openrouter.ts (219, 228, 249) and once in google.ts (169), each slightly differently. `error_kind` feeds the Usage tab (group 14), so its reasons differ by provider for the same event. One `fetchFailure(err, label)` for the two plain-fetch adapters (abort → `aborted`, `LlmError` passed through, SyntaxError → unreadable, fetch's TypeError → network only before the body, mid-body → one agreed kind) in a small `llm/http.ts`. certain.

5. **The plain-fetch adapters share a skeleton written twice** — google.ts 237–273 + 292–303 and openrouter.ts 208–251 + 156–168: POST JSON; on non-OK read the text, try JSON for a message, throw `kindForStatus`; on OK `readSse`, each chunk JSON or `unreadable_response`, an `error` member → `LlmError(kindForStatus(code) ?? "server")`. Plus the fetch wrapper five times (google.ts 53–55, 206–208; openrouter.ts 205, 294–295; googleServiceAccount.ts 99; openrouter.ts 209 also copies to a local, so its wrapper is redundant). Shared: `llm/http.ts` with `plainFetch(f?)`, `postJson`, `errorFromBody(res, label, pick)`, `sseJson(res, onChunk, label)`, used by `streamGemini` and `OpenRouterProvider.send`; and `GoogleProvider`/`VertexGeminiProvider` become one class with a URL+headers strategy (their `send` bodies are the same, google.ts 58–64 vs 214–219). Confirms level 1 (certain).

6. **The answer's post-processing is written in every adapter** — `request.jsonSchema ? withJson(response) : response` four times (anthropic.ts 59, google.ts 63/218, openrouter.ts 128), the model check twice with the same message text (anthropic.ts 57–58, openrouter.ts 127). The port could return the raw response plus an adapter-supplied `answeredBy(asked)` check, and `runCall` (or a wrapper in index.ts) apply the check and `withJson` once; Gemini's "no model check" (documented) is then `() => true`. certain, small.

7. **Error text: three policies** — Claude keeps the provider's whole answer after the status (decided 2026-11-06, anthropic.test.ts 163); Google keeps only `error.message` after a label (google.ts 264–271); OpenRouter "OpenRouter answered N: …", the nested provider message cut to 500, or the body cut to 300 (openrouter.ts 231–238, 87). The UI wraps long errors (style guide), so the cuts aren't needed for layout. Settle one rule ("label: status, the provider's message, the whole body when it isn't JSON") and apply it in `errorFromBody` (5). check (a decision for the plan).

8. **`@google/genai` imported at run time for two enums of strings** — google.ts 1–8: `FinishReason` and `ThinkingLevel` are values, so the 12 MB package (its `dist`) enters the Worker's bundle as far as esbuild can't shake it; `toParams` builds the SDK's `GenerateContentParameters` only for `toRestBody` to take it apart (184–191). With string literals and `import type`, the SDK costs nothing at run time; `toParams` + `toRestBody` become one function building the REST body. check (measure the bundle with and without; the free plan's Worker limit is 3 MB compressed).

9. **Effort and thinking are mapped per family, not per provider** — `EFFORTS` (models.ts 47) gives Claude `xhigh` and `max` on every provider; OpenRouter receives them verbatim as `reasoning.effort` (openrouter.ts 46), which OpenRouter may not take ("max" especially; its models API lists `reasoning.supported_efforts`, docs/llm.md 20, unused). `adaptiveThinking` is read only by the Claude adapter: the same listed Claude model thinks adaptively on Anthropic/Bedrock and not on OpenRouter (unless an effort is given). Group 11/12 own the lists; here: the adapter is where the mapping must live (as Gemini's `THINKING_LEVELS` does). check (try with a Test; level 1 check confirmed as open).

10. **`maxOutputTokens` optional, so the providers' defaults differ** — Claude 64 000 (anthropic.ts 15, `max_tokens` is required by its API), Gemini and OpenRouter the provider's default. Every caller in the app sends it (each run*.ts, the Test 4000); only `try-llm.ts` omits it. Making it required in `LlmRequest` removes the constant and the difference. Level 1 check → narrowed to this. certain, small.

11. **The token fetch can't be stopped, and a token-endpoint outage is "auth"** — googleServiceAccount.ts 55–62: no signal or timeout (deliberately shared by concurrent requests through `pending`, so the caller's signal can't simply be passed); a hanging token endpoint holds the call past Stop and past `withTimeout` (it is awaited in `streamGemini` 241 before `fetch` gets the signal). And any non-OK status is `auth` (not retryable), a 5xx included. Fix: `AbortSignal.timeout(30 s)` on the shared fetch, and `Promise.race` the caller's signal in `getRequestHeaders`; `kindForStatus` for ≥ 500. check, low likelihood.

12. **`TokenSource.projectId` and its comment are left from the Vertex SDK** — googleServiceAccount.ts 38–42, 71: no reader (grep); google.ts reads `account.projectId`. Remove. Level 1 check confirmed. certain, trivial.

13. **`raw` isn't the same kind of record everywhere** — Claude: the SDK's final message; Gemini: the merged chunks, thoughts kept (docs: "a true record of what the provider sent"); OpenRouter: a reconstructed completion that drops the reasoning text and every chunk's extras (openrouter.ts 183–191). If the record should be true, `CompletionStream` keeps the reasoning (and native ids) too. check (docs/llm.md decides how faithful `raw` must be).

14. **Tests: no contract test across adapters** — each adapter's file tests its own mapping; nothing runs the same table (abort, 401, 429, 524, a cut stream, broken JSON, a refusal, usage with cache) through all four, which is how 4 and 7 drifted. Gaps: abort tested for none of Claude/OpenRouter/Gemini-direct (the route relies on `kind === "aborted"`, group 08 #8); the strict-`this` fetch only for Vertex; retries (2) never with the production default. SSE fixtures framed by hand three times (google.test.ts 9 `sse`, exported and unused elsewhere; vertex.test.ts 96, 208; openrouter.test.ts) — use the `sseData` encoder proposed in group 08 #12. vertex.test.ts 196–219 retests `streamGemini` (also in google.test.ts 131–160). One `adapters.contract.test.ts` with a fake fetch per adapter. certain (gap).

15. **Base64 by hand, confirmed across groups** — googleServiceAccount.ts 120–131 (`pemToDer` via `atob` + `charCodeAt`, `base64url` via a char loop + `btoa`), llmRoutes 501 `base64Bytes`, web llm.ts 87–92, imaging fingerprint.ts 35. One `packages/core/src/base64.ts` (bytes ↔ base64, base64url) for the Worker, the web and the desktop; `imaging` keeps its copy or gains a dependency on core (group 01's boundary question). `Uint8Array.fromBase64/toBase64` would do where every host has it (Workers yes, Node 22 no: the desktop and the tests), so not yet. Settles group 01 #15 and group 08's hand-off. certain.

16. **Small ones** — `bedrockModel` (index.ts 66–73) belongs beside its inverse `bedrockNames` in anthropic.ts (certain, placement). The stale Vertex comment and branch in anthropic.ts 153–154: no Claude-on-Vertex adapter exists, and no token source is wrapped by the SDK any more, so `err.cause instanceof LlmError` can't happen (certain, dead). `if (data === "[DONE]")` twice (openrouter.ts 157, 243, certain). `fetchFn ??=` after a default parameter (openrouter.ts 295, certain). `llmRoutes.ts` 14 imports `cloudflareTimeoutMessage` from `./llm/types.ts` while everything else comes through `./llm/index.ts` (certain, trivial). `ADAPTERS` exported without outside users (certain, trivial; goes with 3).

## For level 3
- **The port is narrower than its types:** `id`, `provider`, `retryable`, `servedBy` beside the route's own knowledge, optional `maxOutputTokens` — the component review of the LLM path (groups 08, 09, 12, 13) should fix what the port really carries: request in; text, stop, usage, cost-if-reported, raw out; one error kind table.
- **No retry policy anywhere, except the one an SDK brings by default** (2): decide it at the level of the call recorder (group 08 #7), since a retry is a billing question.
- **Constructors that throw are part of the refusal contract** (1): `prepareCall`'s refusals (cap, secret, unsupported) and the adapters' credential checks should be one list of codes (group 07 #8's `ErrorCode`).
- **`error_kind` is a cross-component contract** (4): adapters write it, the Usage tab (group 14) explains it; nothing pins them together.
- The OpenRouter price lookup lives in the adapter file but serves the cap and the form (groups 11, 13): it is about prices, not calls.

## Patterns
- **Each adapter written in its own session, after the previous one, copying its shape but not extracting it** (5, 6: the plain-fetch skeleton twice, post-processing four times, the fetch wrapper five times; 4, 7: the copies then drifted in error kinds and texts). Count: 4 duplications, 2 drifts. Cause: a second adapter was added by copying the first rather than making the shared part a helper; the third (OpenRouter) was written with plain fetch beside the Google one without looking at `streamGemini`.
- **An SDK default taken unknowingly** (2: retries; also 8: an SDK imported for its enums). Count 2. Cause: the tests set `maxRetries: 0` for speed, so the default never showed; nobody asked what the SDK does on its own.
- **Fields kept for a design that changed** (3: `ProviderId` "until the adapters take the pair themselves"; 12: `TokenSource.projectId` for a removed SDK; 16: the Vertex branch). Count 3. Cause: refactors that added the new path (pairs, REST calls) and left the old one marked "old" rather than removing it.
- **A throw where the caller expects a return** (1). Count 1. Cause: the constructor's validation was written for the script (`try-llm`), where a throw is fine; the route was written against `prepareCall`'s refusal shape and never saw it.
- **Per-family settings applied to every provider** (9). Count 1. Cause: efforts were designed with the family when OpenRouter (a provider of both families) didn't exist yet.
- **Tests per adapter, none across them** (14). Cause: each adapter's tests written with it; the contract between them lives only in `types.ts`'s comments.
