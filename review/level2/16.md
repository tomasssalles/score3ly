# Level 2, group 16: The lens and its writers

## Map
- **notation symbolic.ts** (637 lines): the symbolic format. Closed token lists (`ACCIDENTALS`, `NOTE_VALUES`, `DYNAMICS` = graded + accent, `ORNAMENTS`, `OTHER_MARKS`, `PEDAL`, `POST_COMMANDS`, `EVENT_COMMANDS`, `CLEFS`, `JUMPS`, …), `LENS_VERSION`, lexer and parser → `Event[]`, `walk`, `normalizeClef`. No imports.
- **notation durations.ts / fraction.ts:** exact rationals; a duration's value, `eventsDuration`, `parseTime`, `parseKey`, `measureLength`. Used only inside notation (grep: no app imports them).
- **notation lens.ts** (492): the lens's types (`LensSystem`, `LensStretch`, …) and their enum constants (`STRETCH_CLASSES`, `MEASURE_KINDS`, `BAR_LINES`, `GROUP_SYMBOLS`, `ISSUE_CLASSES`); `checkSystem` (structure → unusable; code issues; spans; durations and measure counting; state carried). Measure counting has a second, whole-piece copy in score.ts `pieceMeasures` (group 17's file, this group's contract).
- **prompts lensForm.ts:** the lens's model form (no nulls, merged class, ending enum + label) both ways, per staff/group/voice/stretch/issue; its own copies of four enum lists.
- **prompts extract.ts:** `MUSIC` (the format's description, its token lists generated from symbolic.ts), `LENS_PITFALLS`/`lensRecap`, `EXTRACT_SYSTEM` (the JSON fields described in prose), `LENS_SCHEMA_PARTS`, `EXTRACT_SCHEMA`.
- **prompts applyReview.ts (types):** `Apply*Unit` restate lens types; `applyReviewFromModel`.
- **Dependencies:** prompts → notation (package.json), but only through the subpath `@score3ly/notation/symbolic` (extract.ts 24); lensForm.ts imports nothing. apps/web runs `lensFromExtract` → `checkSystem` (runExtract), `applyReviewFromModel` → `checkPatch` → `applyPatch` → `checkSystem` (applyReview), and writes the model form back with `*ForModel` (review.ts, runApplyReview.ts, applyReview.ts).
- **Contracts:** (a) token lists: prompt ↔ parser (pinned both ways, prompts extract.test 8) ↔ spans.ts ↔ mei.ts (not pinned); (b) the prompt's prose rules ↔ `checkSystem`'s structural rules; (c) the schema's enums ↔ lens.ts's constants (pinned by apps/web/src/extract.test.ts 44–53); (d) model form ↔ code form (lensForm, round-trip tested); (e) measure counting lens.ts ↔ score.ts (not pinned); (f) texts and schemas ↔ `*_PROMPT_VERSION`/`LENS_VERSION` in the stage keys (by hand).

## Findings

1. **"The stretch's multi-measure rest" is defined three ways, and the prompt makes one of them reject valid answers.** lens.ts 207–208 (structure): a voice is a multi-measure rest when its events, minus `clef`/`ottava`/`stem`, are exactly one `measureRest`; lens.ts 347/362 (counting): the first top-level `measureRest` of any voice, if its count > 1; score.ts 124–133 `restCount`: the first `measureRest` of the first voice that has one (parsing the strings a third time). Consequences:
   - The prompt says tempo marks, breath marks, caesuras and navigation signs are written "in the voice they are printed at" (extract.ts 75, 85). `\tempo "Allegro" R1*4` in the top staff's voice and `R1*4` in another: the first voice's count is null (the `tempo` event isn't filtered), the second's 4 → "every voice must be one, with the same count" → the whole answer unusable (and re-served from the cache on retry, group 10 #1's mechanism). Same with `\segnoMark`, `\breathe`, `\change Staff`.
   - Conversely a voice `R1*2 c4` isn't "one multi-measure rest" for the structural check, so nothing fails, but both counters count 2 measures, no measure is opened (no duration warning, lens.ts 368–369), and the MEI gets a `multiRest` followed by a note (mei.ts 702).
   One helper in notation (e.g. `multiRest(events): {count, duration} | null` = the voice's only event that takes time is a `measureRest`, zero-time events ignored), used by lens.ts (both places) and score.ts; with a test for the tempo case. **certain** (mechanism), **check** (how often: needs several resting staves with a tempo/segno on some).
2. **Measure building twice, agreeing today, pinned by nothing** — lens.ts 309–382 (incremental, per system, for counts, offsets and duration warnings) and score.ts 138–179 (whole piece, for the MEI's measures and numbers). Compared rule by rule: new/continues/none, an orphan "continues" starting a measure of unknown kind, multi-rest counts (but see 1), the measure's time from the top staff with changes applied at the stretch (also on "none" stretches), reset at a piece's start — they agree. They differ by design in the start of numbering (lens counts from 1; score.ts picks 0 for a pickup when the printed numbers match better), harmless since lens.ts only warns where the offset *changes*. Shared: a `measureStep(state, stretch, multiCount)` reducer in notation, which lens.ts calls per stretch and score.ts folds over the piece; at least a test that `checkSystem`'s final `state.count` equals the sum of score.ts's measure counts on the existing multi-system tests. **certain** (duplication), **check** (merge or pin).
3. **The lens's enums restated in prompts, and pinned by a test in the wrong package instead of an import** — lensForm.ts 13 `RIGHT_BAR_LINES` = `BAR_LINES`, 14 `GROUP_SYMBOL_VALUES` = `GROUP_SYMBOLS`, 11 `STRETCH_CLASS_VALUES` = `MEASURE_KINDS` × "new-" + the rest, extract.ts 282 `["reading", "format"]` = `ISSUE_CLASSES`. prompts already depends on notation, but imports only the `/symbolic` subpath. apps/web/src/extract.test.ts 44–53 checks the copies against notation's lists. Fix: import from notation (root, or a `./lens` subpath beside `./symbolic`); derive the class values **in today's order** (`["new-normal", "new-incomplete", "new-unmeasured", "continues", "none"]`): `STRETCH_CLASSES` is `none, new, continues`, so the obvious derivation reorders the enum, changes the emitted schema and with it every request key (group 10's warning). The web test then shrinks to the class derivation and belongs in prompts. **certain**.
4. **`ApplyVoiceUnit`/`ApplyStretchUnit`/`ApplySystemUnit` restate the lens's types by hand** (prompts applyReview.ts 146–174), with literal unions for the class, kind, bar lines and group symbols. `applyPatch` (apps/web/src/applyReview.ts 79–81) spreads a stretch unit's fields over a `LensStretch`, so a field added to `LensStretch` and the schema but forgotten here is invisible to TS. Derive: `ApplyStretchUnit = Omit<LensStretch, "voices"> & { system: number; reason: string | null }`, `ApplySystemUnit = Pick<LensSystem, "startRepeat" | "staves" | "groups" | "lastMeasureContinues"> & {…}`, `ApplyVoiceUnit = Omit<LensVoice, "music"> & { music: string | null; … }` (type-only imports from notation). **certain**.
5. **A system's model form written five times; lensForm.ts has per-field converters but no system-level ones.** From the model: `lensFromExtract` (lensForm.ts 74–83) and the `systems` branch of `applyReviewFromModel` (applyReview.ts 189–193, with its own `each` 182, = lensForm.ts 18, and its own `record` guard 190–191). To the model: apps/web review.ts 59–70, runApplyReview.ts 416–425, applyReview.ts 303 (each mapping `staffForModel`/`groupForModel`/`stretchForModel` by hand; the `measureOf` map is also built twice, review.ts 50 and runApplyReview.ts 410). Add `systemFromModel`/`systemForModel(answer, { measureOf, descriptions })` to lensForm.ts and export `each`. Whether review's and apply_review's score views must differ (descriptions dropped vs kept) is group 18's (group 10, "for level 3"). **certain**.
6. **The ending table twice** — lensForm.ts 34–40 `ENDINGS` and its inverse as a nested ternary in `stretchForModel` 96; invert the table instead. **certain** (minor).
7. **Closed token lists copied by hand, and their readers aren't exhaustive.** The dynamics list written out in spans.ts 105 and mei.ts 904 (`DYNAMICS` exists, symbolic.ts 22); `allowedOnRest` (symbolic.ts 411) = `ORNAMENTS` + `OTHER_MARKS` by hand. And mei.ts `command` (893–934) is an if/else chain over string names, the `event` case (mei.ts 730–734) maps any `EVENT_COMMANDS` name it doesn't know to `"fine"`. The token-list test pins prompt ↔ parser only; a token added to symbolic.ts appears in the prompt, parses, and is then silently dropped from the MEI (or written as "Fine"). Fix: use the constants; make the readers total over the lists the way `JUMP_FUNC` already is (mei.ts 274, `Record<(typeof JUMPS)[number], string>`) — a `Record<(typeof POST_COMMANDS)[number], …>` or a switch with a `never` default — so TS catches the next token. **certain**.
8. **Parser rules the prompt doesn't state.** `allowedOnRest` refuses articulations, fingering, ornaments, arpeggio, glissando and l.v. on rests; the prompt says only "Curves are on notes and chords, never on rests" (extract.ts 60). One unstated rule broken = a whole system's answer unusable. Prompt content, for the task "Check the prompt … of `extract`". **check**.
9. **The check's messages speak the code form; two of its rules can't fire on a model's answer.** lens.ts 144 and 184 ("its description must be null"), 161 ("so it has no kind (null)") — the model wrote `""`, and the user reading the unusable reason sees `""` in the raw answer. 160–161 (class/kind mismatch) can't happen after `stretchFromModel` (the merged class always yields a consistent pair); they only guard stored lens. Say "empty" / reword; keep 160–161 as a guard with a comment. **certain** (minor).

A test that pins a hash of each stage's texts and schema to its version (fails until the version is raised and the hash updated) would close it. ## Patterns
- **A list or type restated in the consuming package instead of imported** (enum lists ×4, `Apply*Unit` ×3, dynamics ×2, `allowedOnRest` ×1): 10. Likely cause: prompts written to stand alone and import only the subpath it first needed; the drift then guarded by a test in another package rather than removed by an import.
- **One rule computed in several places with diverging definitions** (multi-measure rest ×3, measure counting ×2, ending table ×2, system model form ×5, breve ×4): 5 findings. Likely cause: the incremental per-system check and the whole-score builder each written their own walk; each new stage writing the model form inline instead of adding a converter to lensForm.ts.
- **Readers of closed lists not exhaustive** (mei `command`, the event ternary): 2. Likely cause: if/else chains on strings where a typed `Record` was used elsewhere in the same file.
- **Prompt text and code's rules out of step** (tempo in a multi-rest voice, rest marks unstated, messages in code form): 3. Likely cause: the prompt's prose and the checks are edited separately; only the generated token lists are tied.
- **Seams tested in the wrong place or not at all** (enum test in apps/web, model form → check, lens ↔ score counts): 3. Likely cause: tests written for the module being built, not for the contract between two packages.
- **Hand-raised versions without a guard, and docs restating them** (prompt versions; docs at 6/5/6): 2. Likely cause: version bumps remembered by convention; docs quoting a number that changes.
